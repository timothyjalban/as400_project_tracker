Layout concepts for Order Tracker

Two problems, mocked up with the app's real vocabulary so they're easy to react to: the top action bar has grown to twelve same-weight buttons in four unlabeled colors, and the order list / order detail split is a fixed 90/10 divide that doesn't flex with what you're doing. Everything below is inert — click around, nothing calls the real app.

🌙 Dark only, on purpose — mirrors the product's existing theme rather than proposing a new one.

Combined — A + B3 + B1's collapse

SELECTED DIRECTION

The three picked pieces, as one interface instead of three isolated demos: the grouped toolbar on top, a list pane that collapses when the detail side needs the room, and a tabbed detail pane instead of one long scroll. Try it end to end — collapse the list, switch tabs, select a different order.

1 · The action bar

CURRENT → OPTIONS

Right now every button gets a different saturated color, so color reads as "which button is this" instead of "how urgent is this." That's the actual fix — not necessarily hiding actions, just letting a neutral surface carry most of them and reserving color for the one or two that deserve it.

2 · List + detail split

4 PATTERNS

This is the real "master–detail" pattern — same shape as Gmail, Linear's issue list, or a Finder/Explorer window. The question isn't really the split itself, it's how fixed that split should be, and whether "detail" should mean one long scroll or something more structured. Four concrete variants, roughly cheapest → biggest change.

Not a replacement for the list — a second mode next to it, the way Asana or Linear let you flip between list and board. The order tracker's whole reason for existing is a 17-step pipeline; today the only way to see "what's stuck where" across every order is scanning stage-badge text down the left column. A board makes that the actual picture, and dragging a card between columns is the stage-change action.
Only real way to see pipeline distribution across all orders at once, not just one at a time
17 stages is a lot of columns — needs column grouping/scrolling, and it's genuinely new surface to build, not a reshuffle

If I had to pick a first step

  • 1A (grouped bar) — nothing here requires a new interaction pattern, and it fixes the thing you actually flagged first: the toolbar "could look nicer."
  • 2B3 (tabbed detail) pairs naturally with it — same fixed-split shell you have today, just restructures what's inside the right pane. Lowest-risk fix for "the detail side feels like a lot."
  • 3Treat B2 (drawer) and B4 (board) as later, bigger decisions — both are genuinely good patterns (they're how Linear and Asana do this), but they change how the app is navigated, not just how it looks, so they deserve their own conversation once 1–2 are live and you've felt where the current layout still pinches.
